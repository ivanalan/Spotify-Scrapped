Not allowlisted — gate explorations

After Spotify OAuth, Dev Mode rejects accounts that aren’t on the Dashboard allowlist (not_allowlisted). Today that lands as a muted caption on the normal auth gate. These three phones try a clearer system-state story with waitlist as the forward path — no “Sign in” loop.

Design notes (not locked)

  • Hide or demote Sign in on this state — the scar was a silent bounce loop back through Spotify.
  • Prefer “system capacity” language over “you’re not allowed” / raw Spotify prose.
  • Waitlist helper should stress Spotify account email (matches existing gate form + About).
  • Optional: prefill email if we ever have a display name / profile hint; “Tried as @name” is exploratory only (we may not have profile after a failed token exchange).
  • View an example (D-024) is a good secondary escape so the moment isn’t a dead end.
